# 文章格式规范

这是本站文章的**唯一**书写格式。解析器 (`scripts/markdown.ts`) 只认这里列出的构造,
其他 Markdown 写法会**直接报错并中断构建**,并指出文件名和行号。

这么做是故意的:不支持的写法如果被静默忽略,你会得到一个"写了但页面上没有"的文章;
报错的话,你立刻就知道该怎么改。

随时可以校验:

```bash
bun run content:check
```

---

## 1. 文件位置与命名

```
content/
  journal/     个人感受记录
  computing/   计算机技术博客
  comms/       通信工程博客
```

- 一篇文章 = 一个 `.md` 文件,**必须**放在上面三个目录之一。目录名决定分类。
- 文件名就是 URL 里的 slug。只能用小写字母、数字、连字符,例如 `false-sharing.md`
  → `/computing/false-sharing`。
- 想让文件名和 URL 不一致,在 frontmatter 里写 `slug`。
- 新增分类要先在 `src/site.config.ts` 的 `categories` 里声明,否则目录会被判为非法。
- 每个已声明的分类**至少要有一篇**文章(首页的卡片会链到它,空分类是死链)。

### 1.1 专栏(合集)

**分类目录下面的一层子目录就是一个专栏**,放进去的 `.md` 自动属于它:

```
content/
  computing/
    stream.md              散篇  → /computing/stream
    web-arch/              专栏  → /computing/web-arch
      intro.md                   → /computing/web-arch/intro
      rendering.md               → /computing/web-arch/rendering
```

散篇的地址不受影响,加专栏不会动到任何已有链接。

专栏和分类做同一笔交易:**目录要先声明,否则构建失败**。在
`src/site.config.ts` 的 `series` 里加一条,`slug` 与目录名一致:

```ts
export const series: SeriesMeta[] = [
  {
    slug: "web-arch",        // 必须等于目录名,同时是 URL 片段
    category: "computing",   // 所属分类,也就是父目录
    title: "Web 架构漫谈",
    titleEn: "Web Architecture",
    summary: "从单页应用到服务端渲染,逐篇拆开现代 Web 的分层",
    intro: "这个专栏按顺序讲清楚一件事:浏览器里的那一屏,是谁在什么时候算出来的。",
  },
];
```

不这么做的话,一个手滑打错的目录名会变成一个没有标题、没人链接、自己也不知道存在的
专栏 —— 和未声明的分类一样,报错比静默接受有用。

**专栏内的次序由 frontmatter 的 `order` 决定,不看日期。** 专栏是一条阅读路线,最新
的一篇应该排在最后而不是最前。规则和有序列表一致:

- 专栏里的每篇都**必须**写 `order`,从 1 开始连续递增、不重复。
- 散篇**不许**写 `order`,否则报错 —— 写了却不生效是这份格式最想避免的事。
- 编号断号(1、2、4)或重复会中断构建,因为那会让"第 4 篇,共 3 篇"和"上一篇"同时失去
  意义。

其他几条约束:

- **目录最多两层**。`content/computing/web-arch/deeper/x.md` 会报错,再深一层在 URL
  里没有位置。
- 专栏的 `slug` **不能和同分类下某个散篇的 slug 同名**,两者都要占用
  `/computing/<slug>`,谁赢取决于路由顺序而不是你能看见的东西。这种情况会报错。
- 已声明但一篇文章都没有的专栏**不是错误**,只会在编译输出里提示,页面显示占位状态。
  否则把一个专栏清空就变成一次没法提交的改动。

页面上会多出三处:

- 专栏索引页 `/<分类>/<专栏>`,按序列出全部文章
- 文章页标题上方一条"所属专栏 · 第 N / M 篇"的横幅,可点回索引页
- 左侧目录按专栏分组,专栏在前、散篇在后;**专栏内的"上一篇 / 下一篇"走的是
  `order`**,而不是分类的日期序

## 2. Frontmatter

文件必须以 `---` 开头,YAML 块,再以 `---` 收尾。

```yaml
---
title: 缓存行、伪共享,与一次三倍的性能回退
lede: 两个线程各写各自的计数器,中间没有任何锁,吞吐却掉到了单线程以下。
date: 2026-07-02
tags: [Performance, Cache, Systems]
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题。页面的 `h1`,也是左侧目录里的条目名 |
| `lede` | 是 | 导语。排版上比正文大一号,位于标题下方的横线之后 |
| `date` | 是 | `YYYY-MM-DD`。用于显示和排序(新的在前),会校验是否为真实日期 |
| `tags` | 否 | **关键词**。字符串数组,渲染成标题下面那排方框标签。省略则无标签 |
| `slug` | 否 | 覆盖由文件名推出的 URL 片段 |
| `draft` | 否 | `true` 时跳过该文件,不参与构建 |
| `order` | 看位置 | 在专栏里的次序,从 1 开始的正整数。**专栏目录下必填,散篇不许写**,见 1.1 |
| `kind` | 否 | **只用于杂谈**,文章写了会报错。见第 9 节 |
| `author` | 否 | **只用于杂谈**,文章写了会报错。见 9.1 |

上表是**文章**的契约。杂谈(`content/others/`)用的是另一份,`lede` 可选而 `kind` 必填,见 9.1。

写了表格里没有的字段会报错 —— 这样 `titel` 这种拼写错误不会被无声吞掉。

> 注意:标题或导语里出现英文冒号加空格(`: `)时,YAML 会把它当成键值分隔。
> 这种情况把整个值用双引号包起来:`title: "链路预算:把 dB 当成一种记账方式"`。

## 3. 正文构造

### 3.1 段落

空行分隔。段落内可以硬换行,**换行处两侧都是中日韩文字时不会插入空格**,
所以你可以在编辑器里按喜好折行:

```markdown
这是一个很长的段落,
折行之后渲染结果里不会多出空格。

这是另一个段落。
```

段落后面紧跟标题、列表、代码围栏或引用时**不需要空行** —— 写"如下所示："然后直接
换行开代码围栏是可以的。唯一的例外是分隔线 `---`,它前面必须空一行,否则无法和
setext 标题区分。

**强制换行**:写一个反斜杠,后面跟空格或直接到行尾。

```markdown
北京市海淀区中关村大街 1 号\
邮编 100080
```

规则就一条:**反斜杠紧跟空格或处于末尾时就是换行**,其他情况下它还是转义符。

- 因为判据是「后面是空白」而不是「在行尾」,所以它在**单行构造里也能用** ——
  最有用的场合是表格单元格,见 3.7。
- 字面反斜杠写成 `\\`。行尾的反斜杠按个数判断:奇数个表示最后一个是换行符,偶数个
  表示它们都是转义对,这一行照常折行。
- 为什么 `\ ` 可以被征用:转义一个空格本来就没有任何意义,这个写法原先是空的。
- **不支持 `<br>`**,也不支持"行尾两个空格"那种写法。前者是 HTML,这份格式不收 ——
  理由见第 6 节;后者在编辑器里不可见,保存时经常被自动去掉。
- 想要整段保留换行的是**诗**,用 ```verse 围栏(见 3.11),那是另一种排版
  (楷体、放大、行距加宽)。这里这个是给散文里偶然需要断一行的情况用的。

### 3.2 小节标题(决定左侧目录)

**左侧目录就是从 `##` 和 `###` 自动抽出来的**,不需要手写目录。

```markdown
## 二级小节

### 三级小节
```

- `#` 一级标题**不允许** —— 它由 frontmatter 的 `title` 承担。
- `####` 及更深**不允许**,只有两级。
- `#` 后面必须有空格。
- 锚点 id 由小节在文中的位置自动生成(`h-3` 这种),无需也无法手写。

### 3.3 无序列表

```markdown
- 第一项
- 第二项
```

- 只能用 `- `,不能用 `*` 或 `+`。
- **列表项的文字必须单行**,不支持折行续写。
- 项与项之间可以空行(渲染结果一样),遇到不是列表项的行则列表结束。
- 项下面可以挂缩进的块,见 3.5。

### 3.4 有序列表

```markdown
1. 第一步
2. 第二步
3. 第三步
```

序号**必须从 1 开始连续递增**。写成全 `1.` 或者跳号会报错 —— 这样文中引用"第 3 步"时
序号一定是对的。项之间同样可以空行。

### 3.5 列表项下面挂块

把内容**缩进**到列表项下面,它就属于那个项。最常见的用法是每一步配一段代码:

````markdown
1. ini:

    ```ini
    database.host="localhost"
    ```

2. yaml:

    ```yaml
    database:
      host: localhost
    ```
````

规则:

- 缩进多少都行(两个空格以上),同一段里保持一致即可 —— 解析时按这一段里最小的缩进量整体剥掉。
- 缩进块里可以放代码围栏、段落、表格、公式,也可以再放一层列表。
- **不能放 `##` / `###` 小标题**,会报错 —— 否则左侧目录的层级会乱掉。
- 缩进只在列表项下面有意义。**正文里无故缩进仍然报错**,因为那通常是手滑或者在尝试写缩进代码块。

### 3.6 代码块

用三个反引号围栏,后面紧跟语言名(可省略)。语言名会以小字显示在代码块左上角。

````markdown
```ts
const a = 1;
```
````

- 围栏内是纯文本,不解析任何标记。想展示表格、ASCII 图、命令行输出,都放这里。
- 必须闭合。
- **不支持缩进代码块**(四个空格那种),行首有缩进会报错。

### 3.7 表格

```markdown
| 字体 | 真粗体 | 默认装了吗 |
| --- | --- | --- |
| SimSun 宋体 | 没有 | Windows 自带 |
| 微软雅黑 | 有 | Windows 自带 |
```

- **必须有一行 `| --- |` 分隔行**,这是表格和"恰好含竖线的段落"的唯一区别。分隔行至少三个短横。
- 第一行内容是表头。至少两列,只有一列用列表更合适。
- **每行的单元格数必须和表头一致**,不一致会报错并指出行号。GFM 会悄悄补齐或截断,这里不会。
- 两侧的竖线可写可不写,`a | b` 和 `| a | b |` 等价。
- 单元格里要写字面竖线就转义成 `\|`;反引号代码里的竖线不用转义,`` `a|b` `` 照常。
- **单元格内换行**用反斜杠加空格(见 3.1)。一格里要并列几条的时候用得上:

  ```markdown
  | 目前情况 |
  | --- |
  | 11k, 国企, 月加班 64h\ 9k, 国企, 硬件运维\ 9k6, 大厂, 大堂经理 |
  ```

  仍然**不支持**把单元格写成跨多行的源码 —— 一行一格的规则没变,换的是渲染出来的行。
- 装饰性的分隔行会被忽略,所以首尾各加一行 `| --- |` 画成完整边框也能正常解析。对齐取表头下面那一行。

对齐用冒号:

```markdown
| 左 | 居中 | 右 |
| :--- | :---: | ---: |
| a | b | c |
```

渲染成只有横线、没有竖线的表格:表头下面一道粗线,行间细线,数字按等宽对齐。
**宽度按内容收缩**而不是撑满整栏 —— 几个短单元格被拉开满屏的话,行就不成行了。
内容宽到超出正文栏时,表格自己横向滚动。

### 3.8 引用

```markdown
> 链路预算不保证系统能工作,它只保证你知道自己假设了什么。
```

想标出处,最后一行用 `-- ` 或 `— ` 开头:

```markdown
> 测量不改变事实,但它改变了我和事实之间的距离。
> -- 出处
```

### 3.9 提示框

GitHub 风格的 alert 语法,渲染成带分类强调色底纹的 Note 块:

```markdown
> [!NOTE]
> 填充会放大内存占用。计数器这种少量、高频写的结构值得填充。
```

目前只有 `[!NOTE]` 一种。

### 3.10 图片

单独一行,标准 markdown 语法。方括号里是替代文字,圆括号里是**相对于当前 .md 文件**的
路径,引号里是可选的图注:

```markdown
![PA 的 AM-AM 特性曲线，接近饱和时增益被压缩](./amam.png "图注写在这里")
```

- **替代文字必填**,留空会报错。读屏软件和图片加载失败时都只剩它。
- **图片必须独占一行**,不能插在段落中间,否则报错。
- 路径必须是相对路径,而且解析后要落在仓库里面。外部 URL 会报错 —— 那种图不会随站点
  一起部署,哪天对方挂了你的文章就缺图。
- 找不到文件会**中断构建**并打印解析后的完整路径,不会发布一个坏图上去。
- 支持 `png` `jpg` `jpeg` `gif` `webp` `svg` `avif`。

注意相对路径的起点是 **.md 文件所在目录**。在 `content/comms/x.md` 里写
`./../src/comms/a.png`,`../` 退到的是 `content/`,所以指向 `content/src/comms/a.png`,
不是仓库根目录下的 `src/`。要指到仓库根的 `src/` 得写 `../../src/comms/a.png`。

尺寸规则是:

- **宽度上限是正文行宽**(不是整栏宽)。超过的图自动等比缩小。
- 小于正文行宽的图**不放大**,按原始像素显示,并在正文行宽内**居中**。放大只会变虚。
- 想让图占满正文行宽,就把图导出成大约 1100px 宽;高分屏下想清晰可以再翻一倍。

渲染成一个细线框,内衬一圈留白,图注在图下方居中、带一道强调色短线。

### 3.11 诗(verse)

诗是这份格式里**唯一换行本身就是内容**的构造。普通段落会把硬换行合并掉(见 3.1),
那对散文是对的,对诗是毁灭性的。所以诗用一个专门的围栏:

````markdown
```verse
窗冷灯犹亮
风来纸未翻
一行红字落
又是旧因缘
```
````

- 信息串只能是 `verse`,其他的一律当语言名处理成代码块。
- **每一行原样保留**,不合并、不插空格。
- 行内标记照常解析 —— 和真代码围栏不同,`**强调**`、`[链接](…)`、`$公式$` 在诗里都有效。
- **空行是分节**,渲染成一段垂直留白而不是一个空行。
- 首尾的空行会被去掉,所以围栏内可以留空行让源码好看一点。
- 围栏是空的会报错。

渲染成左边一道细线、Times 排版、行距比正文紧一点的块。换行处理上有个细节:每一行是独立
元素并带悬挂缩进,所以窄屏上折行的那半句会缩进,不会被误读成诗的下一行。

### 3.12 分隔线

单独一行 `---`(frontmatter 之后的 `---` 都当分隔线处理)。

## 4. 行内标记

只有这四种,可以嵌套:

| 写法 | 渲染 |
| --- | --- |
| `` `代码` `` | 等宽字体 + 浅底色 |
| `**强调**` | 加粗,并带一道分类强调色的底纹 |
| `*次强调*` | 加字距 + 强调色下划线(不用斜体,中文斜体不好看) |
| `[文字](地址)` | 链接,带强调色下划线;外链自动 `target="_blank"` |
| `<地址>` | 裸地址,地址本身作为链接文字 |
| 行尾 `\` | 段落内强制换行,见 3.1 |

链接地址只接受:`http://`、`https://`、`mailto:`、站内绝对路径 `/…`、锚点 `#…`、
相对路径 `./…`。其他协议(包括 `javascript:`)会报错。

**裸地址**用尖括号包起来,地址本身就是链接文字:

```markdown
接口在 <http://localhost:5000/radio/164.17.65.34/> 上。
```

- 尖括号里必须是**带协议**的完整地址(`http://`、`https://`、`mailto:` 等),
  且不含空格。这条限制是为了让 `a < b` 这种写法照常当普通文字。
- 地址走和 `[文字](地址)` 完全一样的协议校验。
- 不想让它变成链接就把尖括号转义成 `\<`。

**字面字符**:`*`、`` ` ``、`[`、`]`、`$`、`\` 要按字面显示时,前面加反斜杠,
例如 `\*`、`\$`。未配对的 `*`、反引号、`**`、`[`、`$` 都会报错而不是被当作普通字符。

## 5. 公式

行内用一对 `$`,独立成块用单独成行的 `$$`:

```markdown
噪声系数 $NF$ 由级联决定，第一级是 $F_1$。

$$
F_{\mathrm{total}} = F_1 + \frac{F_2 - 1}{G_1} + \cdots
$$
```

几条必须知道的规则:

- **`$` 之间的内容整段交给 KaTeX,反斜杠不再是 markdown 转义。** 写 `\frac` 就是
  `\frac`,不要写成 `\\frac`;反过来 `\\` 在 LaTeX 里是换行符,基本不是你想要的。
- **下标超过一个字符必须加花括号。** `f_{LO}` 才是 f 下标 LO,而 `f_LO` 是
  「f 下标 L」后面再跟一个普通的 O —— KaTeX **不会报错**,只会默默渲错,这是最容易
  踩的一个坑。
- 函数名和单位用 `\mathrm{}` 保持正体,例如 `$\mathrm{Softmax}$`、`$\mathrm{dBm}$`。
  直接写 `$Softmax$` 会被当成七个斜体变量相乘。
- 公式写错会**中断构建**并指出文件行号。KaTeX 不认识的命令(以及被禁用的 `\href`
  这类)也会报错,而不是在页面上留一段红字。
- 代码围栏和行内代码里的 `$` 不受影响,所以 `` `Bearer ${TOKEN}` `` 照常写。

渲染是在**构建期**完成的:KaTeX 把 LaTeX 转成 MathML,再转成元素树存进产物,浏览器
用原生 MathML 排版。所以前端**不加载任何 JS、CSS 或字体文件**,公式的代价只有产物里
那几百字节的标签。

中文的「」『』(),以及破折号 `——`,都是普通字符,直接写。

## 6. 明确不支持的东西

遇到这些会报错,并给出替代方案:

- 图片的外部 URL(必须是仓库内的相对路径)
- 行内图片(必须独占一行)
- 内嵌 HTML,**包括 `<br>`** → 段落内换行用行尾反斜杠,见 3.1
- 行尾两个空格表示换行(不可见,编辑器会吃掉)→ 同上
- 缩进代码块(四个空格那种)→ 一律用 ``` 围栏;列表项下面的缩进见 3.5
- 表格的合并单元格
- 把一个表格单元格写成跨多行的源码(单元格内换行用 `\` 加空格,见 3.7)
- setext 标题(下面画 `===` 那种)
- 脚注、定义列表、任务列表
- 列表项里的 `##` / `###` 小标题
- `#` 一级标题、`####` 及更深的标题

LaTeX 公式**现在是支持的**,见下一节。

需要其中某一项时,得同时加三处:`src/content/types.ts` 的 `Block` 类型、
`scripts/markdown.ts` 的解析分支、`src/components/ArticleBody.tsx` 的渲染分支。
`ArticleBody` 的 `switch` 有穷尽性检查,漏掉渲染分支是编译错误,不会变成空白页面。

## 9. 杂谈(others)

格言、诗词、生活小 tips 这类**不成篇**的东西放这里,平铺在一个目录下:

```
content/
  others/
    tools-and-habits.md    →  /others/tools-and-habits
    autumn-window.md       →  /others/autumn-window
```

杂谈**不是第四个分类**,这不是为了整齐。`CategoryMeta.position` 的类型是
`"left" | "center" | "right"`,而首页卡片环只有三个工位、靠 `mod3` 绕环,加第四个分类
会把那个环拆掉。更根本的是这些东西形状不一样:没有导语、没有阅读次序、没有侧栏目录。
所以它在 `src/content/types.ts` 里是独立的 `Note` 类型。

**不分子目录。** `content/others/<子目录>/x.md` 会报错 —— 杂谈没有专栏。

### 9.1 杂谈的 frontmatter

和文章是两份契约:

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 标题 |
| `date` | 是 | `YYYY-MM-DD`。首页星图的**横轴** |
| `kind` | 是 | 体裁,见下表。决定星点颜色和弹窗上的标签 |
| `lede` | 否 | **文章必填,杂谈可选** —— 四十个字的格言,导语往往比它本身还长 |
| `author` | 否 | **抄录别人的东西时填**。省略就表示是你自己写的 |
| `tags` | 否 | 同文章 |
| `slug` | 否 | 同文章 |
| `draft` | 否 | 同文章 |

`author` 存在的理由:抄一首李煜的词进来,署名是记录的一部分,不该塞进标题里。填了之后
星图的弹窗、列表和阅读页三处都会显示出处,不会漏掉任何一个入口。文章侧写 `author`
会报错 —— 文章按定义是你写的,要标出处请用引用块的 `-- 出处`(见 3.8)。

`kind` 的可选值在 `src/site.config.ts` 的 `noteKinds` 里声明:

| `kind` | 显示名 | 色调 | 放什么 |
| --- | --- | --- | --- |
| `poem` | 诗词 | clay | 格言、古诗、词、十四行诗。压缩过的、一句顶一段的写法 |
| `tip` | 生活小 tips | birch | 可操作的做法,读完能照着做 |
| `musing` | 向内 | fjord | 具体的、关于自己的。迷茫归这里 |
| `outlook` | 向外 | ink | 宏观的。未来、世界、行业 |

**四类对四个强调色,一对一。** 所以星图上颜色直接就是体裁,不需要打开弹窗才知道是什么:

```
clay   诗           poem
birch  能照着做的    tip
fjord  向内         musing
ink    向外         outlook
```

这个一对一值得守住。再加第五类的话,要么共用色调、打破这个映射,要么往
`src/styles/tokens.css` 里加一个全站都得为它负责的新强调色。

诗的具体体裁不靠 `kind` 区分,靠标题自己说 —— 「虞美人 · 春花秋月何时了」「Sonnet 18」
已经说得比任何标签都清楚了。

感悟是按**朝向**拆的,不是按长短。「下雨天我产出更高,因为外面没有值得看的东西」是向内;
「软件同学的未来在哪里」是向外。同一件事往哪个方向想,读起来是两种东西。

两条互斥规则,和专栏那边同理 —— 写了却不生效比报错更糟:

- 杂谈**不许**写 `order`(没有次序)。
- 文章**不许**写 `kind`(那是杂谈的字段)。

### 9.2 首页那片星图

杂谈在首页渲染成一片星点,**它其实是散点图**:横轴是写作日期,纵轴是篇幅(字数)。

两条轴的值域都是**从实际文章算出来**的,不是写死的,所以四则和四百则都能把这片区域填满。
两件事值得知道:

- **两端都留了余量。** 最长的那篇不会顶在坐标轴上 —— 否则它会被读成轴的一部分而不是数据。
  余量按跨度的百分比算(时间轴 10%,篇幅轴 14%),并各有一个最小值兜底。
- **纵轴用篇幅而不是阅读时长。** `readingMinutes` 是 `max(1, round(字数/340))`,
  20–300 字的杂谈全部会算出 1 分钟,纵轴会退化成一条直线。
- **篇幅的单位是「一个中日韩字符或一个拉丁单词」**,不是原始字符数。这一条是被莎士比亚
  逼出来的:Sonnet 18 按字符数是六百多,而中文杂谈最长两百八,一首英文诗就能把值域撑到
  让所有中文条目挤在顶部一条带里。按词计之后它约 114,落在中间。实现是
  `src/content/types.ts` 的 `textLength`。

重叠的点会被一个**确定性的最小间距松弛**推开。那不是随机抖动:位置仍然从数据来,只在
两点挤到点不中的时候才移动,而且没有任何随机数,所以每次渲染星图长得一样,你能记住东西在哪。

实现在 `src/lib/scales.ts`,星图在 `src/components/OthersSection.tsx`。

**760px 以下星图整体换成列表。** 几个像素的目标手指点不到,那个宽度下列表才是主界面
(用 `display: none` 切换,所以读屏不会读到两遍)。
